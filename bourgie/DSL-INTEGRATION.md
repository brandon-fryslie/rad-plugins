# 🎯 Bourgie DSL Integration Guide

The Bourgie YAML DSL is now a first-class citizen with a Python-based compiler daemon that provides instant compilation and hot reload integration.

## 🏗️ Architecture

```
DSL YAML File (source)
       ↓
Python Compiler Daemon (watches file)
       ↓ (generates)
├── oh-my-posh config YAML
└── zsh functions file
       ↓ (sourced by)
Bourgie Plugin + Hot Reload
       ↓ (renders)
Beautiful Prompt ✨
```

## 🚀 Quick Start

### 1. Install Dependencies

```bash
# Install required Python packages
pip3 install pyyaml watchdog
```

### 2. Create DSL Theme

```yaml
# my-theme.dsl.yaml
version: 3
final_space: true

blocks:
  - type: prompt
    alignment: left
    segments:
      - type: path
        style: plain
        foreground: '#00CED1'
        custom_fn: ->
          local icon="📁"
          [[ "$PWD" == "$HOME" ]] && icon="🏠"
          echo "${icon} ${PWD} "
```

### 3. Initialize DSL Theme

```bash
# Auto-compile and start daemon
bourgie_init_dsl my-theme.dsl.yaml

# Manual compilation only
bourgie_dsl_compile my-theme.dsl.yaml
```

### 4. Enable Hot Reload (Optional)

```bash
# Enable hot reload for instant changes
bourgie_hot_reload on
```

## 🔧 DSL Syntax

### Custom Function Syntax

```yaml
segments:
  - type: text
    style: plain
    foreground: '#00CED1'
    custom_fn: ->
      # Plain zsh code here
      local result="Hello World"
      [[ -n "$SSH_CLIENT" ]] && result="Remote: $result"
      echo "$result"
```

**Key Changes:**
- ✅ Use `custom_fn: ->` for all custom segments
- ✅ Write plain zsh code (no CoffeeScript-style syntax)
- ✅ Functions execute before prompt rendering
- ✅ All functions wrapped in `set_poshcontext()` function

### Example: Complex Custom Logic

```yaml
- type: git
  style: plain
  foreground: '#90EE90'
  custom_fn: ->
    # Check if we're in a git repository
    git rev-parse --git-dir >/dev/null 2>&1 || return
    
    # Get git information
    local branch=$(git branch --show-current 2>/dev/null)
    local status=""
    
    # Check for uncommitted changes
    if ! git diff-index --quiet HEAD -- 2>/dev/null; then
      status=" 📝"
    fi
    
    # Check for staged changes
    if ! git diff-index --cached --quiet HEAD -- 2>/dev/null; then
      status="${status} 📦"
    fi
    
    # Check for stashes
    local stash_count=$(git stash list 2>/dev/null | wc -l)
    [[ $stash_count -gt 0 ]] && status="${status} 📚${stash_count}"
    
    echo "🌿 ${branch}${status} "
```

## 🔥 Compiler & Daemon

### Manual Compilation

```bash
# Compile DSL to oh-my-posh config and zsh functions
bourgie_dsl_compile my-theme.dsl.yaml

# Specify custom output paths
bourgie_dsl_compile my-theme.dsl.yaml \
  --config-output custom-config.yaml \
  --functions-output custom-functions.zsh
```

### File Watching Daemon

```bash
# Start daemon for automatic compilation
bourgie_dsl_daemon start my-theme.dsl.yaml

# Check daemon status
bourgie_dsl_daemon status

# Stop daemon
bourgie_dsl_daemon stop

# Restart daemon
bourgie_dsl_daemon restart my-theme.dsl.yaml
```

### Generated Files

When you compile `my-theme.dsl.yaml`, you get:

1. **`my-theme-compiled.yaml`** - Clean oh-my-posh config
2. **`my-theme-functions.zsh`** - Generated zsh functions

Example generated function file:

```zsh
#!/usr/bin/env zsh

# Generated by Bourgie DSL Compiler

# Custom function: custom_blocks_0_segments_0
function _custom_blocks_0_segments_0() {
    local icon="📁"
    [[ "$PWD" == "$HOME" ]] && icon="🏠"
    echo "${icon} ${PWD} "
}

# Main context setting function - executes all custom functions
function set_poshcontext() {
    # Clear any existing context
    unset _BOURGIE_CONTEXT
    declare -gA _BOURGIE_CONTEXT
    
    # Execute custom_blocks_0_segments_0
    local custom_blocks_0_segments_0_result
    custom_blocks_0_segments_0_result="$(_custom_blocks_0_segments_0)"
    _BOURGIE_CONTEXT[custom_blocks_0_segments_0]="${custom_blocks_0_segments_0_result}"
    export _BOURGIE_CUSTOM_BLOCKS_0_SEGMENTS_0="${custom_blocks_0_segments_0_result}"
}

# Auto-execute set_poshcontext if not disabled
if [[ "$BOURGIE_DSL_NO_AUTO_CONTEXT" != "true" ]]; then
    set_poshcontext
fi
```

## 🔄 Hot Reload Integration

When combined with hot reload, changes to DSL files are instantly visible:

```bash
# Start DSL daemon
bourgie_dsl_daemon start my-theme.dsl.yaml

# Enable hot reload
bourgie_hot_reload on

# Edit my-theme.dsl.yaml in your editor
# Changes appear instantly in your prompt!
```

### Workflow:
1. **Edit DSL file** → File watcher detects change
2. **Python daemon recompiles** → Updates config and functions
3. **Hot reload triggers** → oh-my-posh re-reads updated config
4. **New prompt renders** → Changes visible immediately

## 🎛️ Advanced Usage

### Environment Variables

Control DSL behavior with environment variables:

```bash
# Disable auto-execution of set_poshcontext
export BOURGIE_DSL_NO_AUTO_CONTEXT=true

# Custom daemon PID location
export BOURGIE_DSL_DAEMON_PID=/path/to/custom.pid
```

### Integration with bourgie_config

```bash
# Check DSL daemon status in configuration
bourgie_config status
# Shows:
#   DSL Daemon: running (PID: 12345)
#   DSL Source: my-theme.dsl.yaml
#   DSL Config: my-theme-compiled.yaml
```

### Debugging DSL Issues

```bash
# Enable debug logging
bourgie_config debug on

# Check DSL compiler availability
bourgie_dsl_compile --help

# View daemon logs
tail -f /tmp/bourgie-debug.log

# Test DSL compilation manually
python3 bourgie_dsl_compiler.py compile my-theme.dsl.yaml --verbose
```

## 🏷️ Available Commands

### DSL Management
- `bourgie_init_dsl <file>` - Initialize DSL theme with auto-daemon
- `bourgie_dsl_compile <file>` - Compile DSL to config + functions
- `bourgie_dsl_daemon start <file>` - Start file watching daemon
- `bourgie_dsl_daemon stop` - Stop daemon
- `bourgie_dsl_daemon status` - Check daemon status
- `bourgie_dsl_daemon restart <file>` - Restart daemon

### Hot Reload Integration  
- `bourgie_hot_reload on` - Enable config hot reloading
- `bourgie_hot_reload off` - Disable hot reloading
- `bourgie_hot_reload status` - Check hot reload status

### Configuration
- `bourgie_config status` - Show all configuration including DSL
- `bourgie_config debug on` - Enable debug logging

## 🎯 Best Practices

### 1. **Use Descriptive Function Names**
While the compiler generates names automatically, organize your DSL logically:

```yaml
# Good: Logical segment organization
segments:
  - type: text  # This becomes custom_blocks_0_segments_0
    custom_fn: -> echo "session info"
  - type: path  # This becomes custom_blocks_0_segments_1  
    custom_fn: -> echo "directory"
```

### 2. **Keep Functions Simple**
Each custom function should do one thing:

```yaml
# Good: Simple, focused function
custom_fn: ->
  [[ -n "$SSH_CLIENT" ]] && echo "🔗 SSH " || echo ""

# Avoid: Complex logic that should be split
custom_fn: ->
  # 50 lines of complex logic...
```

### 3. **Use Environment Variables**
Access configuration through environment variables:

```yaml
custom_fn: ->
  [[ "$ENABLE_DOCKER_PROMPT" == "true" ]] || return
  local host="${DOCKER_HOST:-localhost}"
  echo "🐳 ${host} "
```

### 4. **Handle Errors Gracefully**
Always provide fallbacks:

```yaml
custom_fn: ->
  local version=$(node -v 2>/dev/null)
  [[ -n "$version" ]] && echo "⬢ $version " || echo ""
```

## 🔧 Troubleshooting

### Compiler Not Available
```bash
# Check Python and dependencies
python3 --version
python3 -c "import yaml, watchdog"

# Install missing dependencies
pip3 install pyyaml watchdog
```

### Daemon Won't Start
```bash
# Check for existing daemon
bourgie_dsl_daemon status

# Kill stale processes
pkill -f bourgie_dsl_compiler

# Remove stale PID files
rm -f ~/.zgenom/sources/brandon-fryslie/rad-plugins/___/bourgie/.dsl_daemon.pid
```

### Functions Not Executing
```bash
# Check if functions file was generated
ls -la my-theme-functions.zsh

# Check if functions are sourced
type set_poshcontext

# Manually execute context setting
set_poshcontext
```

### Hot Reload Not Working
```bash
# Verify both daemon and hot reload are enabled
bourgie_dsl_daemon status
bourgie_hot_reload status

# Check file permissions
ls -la my-theme.dsl.yaml my-theme-compiled.yaml
```
